# style-spreadsheet

Google スプレッドシートの書式の型。Claude がシートを作る・直すときは、この文書の決まりに従う。

- この文書が決まりの正本。手順と、見本のシート・型を塗る GAS の置き場所は、スキル cl-style-spreadsheet に書く。
- 型を塗る GAS の全文は、同じフォルダの paint.js（4-2.）。
- 1. の共通の決まりはどの型にも当てはめ、2. 以降の型ごとの節で足したり変えたりする。
- この定義で決まらない点、迷う点は、作る前に依頼した人に確かめる。

## 0. 型の一覧

| 型 | 使う場面 | 見本のシート |
|---|---|---|
| 標準 | 決まり・一覧と、その変更の記録を持つ管理用のファイル | 仕様（表1つ）・仕様（表2つ）・ログ・履歴 |

## 1. 共通の決まり

### 1-1. シート全体

- 枠の線（グリッド）を隠す。
- 字の種類は Noto Sans JP。セルの余白は 上2・右6・下2・左6 px。
- 色は黒とグレーだけにし、強調には青1色を使う。条件付き書式は使わない。
- 本文の字の色は #202124、説明・注記などの淡い字は #5F6368。
- 使っていない列と、右端・下端の要らない行・列を消す（行が増えるシートは型の決まりのとおり先に行を残す）。
- 行や列を足したら、その表の書式をいったん消して、型で塗り直す。
- シートの名前を変える前に、その名前で読んでいる GAS・スキル・資料を洗い出す。シートの中の式の参照は自動で直る。

### 1-2. 見出し

- 見出し（題・節・列の見出し）には、説明・括弧書き・件数を書かない。そうした中身は説明の行や注記に書く。

### 1-3. 寄せと折り返し

- 番号・記号・状態（チップ）・短いコードは中央寄せ、数は右寄せ、文は左寄せ。
- 折り返すのは文の列（説明・メモ・条件）だけ。名前やコードの列は右端で切る。
- 1つのセルに名前がいくつも入る列だけは、例外として折り返す。
- 番号・ID の列（R1、T1 など）は太字・中央・右端で切る。

### 1-4. 依頼した人が書き込む列（判断・コメント・確定など）

- 塗りは付けない。線はほかの列と同じにする。
- 列の見出しの字を青（#1A73E8）にし、表示形式 `"✎ "@` で頭に「✎ 」を出す。セルの値は「判断」のままで、✎ も字と同じ青になる。

### 1-5. プルダウン

- チップの形で出す（矢印の形にしない）。チップの字が切れない列幅にする。横に長くなりすぎるときは列を分ける。
- 選択肢以外の入力は拒否する。道具（API）からは選択肢にない値も書けてしまうので、書く前に選択肢と照らし、ない値を書くときは依頼した人に確かめる。
- チップの色は入力規則の色で付ける。選択肢の言葉の意味で振り分ける。

| 色 | 選択肢の例 |
|---|---|
| 赤 | 消す・誤り |
| 紫 | 保留 |
| 黄 | 作る・直す・変える・〔提案〕・未決・見込 |
| 青 | 足す・済・終了 |
| 緑 | 進行中・案どおり・確定 |
| 灰 | 休眠・しない・作らない |
| 色なし | それ以外 |

- 色・チップの形・拒否の設定は、Chrome の「データの入力規則」の画面で付ける。API で入力規則を貼り直すと、色が消えることがある。

## 2. 型：標準

### 2-1. シートの種類と並び

- シートは名前の頭で3種類に分け、仕様 → ログ → 履歴 の順に並べる。頭の付け方は原則で、どれにも当たらない作業用のシートは頭なしでもよい。

| 種類 | 名前 | 中身 | タブの色 | 表示 |
|---|---|---|---|---|
| 仕様 | 仕様_<中身> | 今の決まりと一覧の表 | #4A86E8（青） | 見せる |
| ログ | ログ_<ファイルの名前> | 変えた記録を足し続ける表 | #D9D9D9（灰） | 見せる |
| 履歴 | 履歴_<中身> | 止まっていて、読み返すだけの表（移行の作業、前の案など） | #D9D9D9（灰） | 隠す |

- まだ決まっていない仕様のシートは、名前の後ろに「_仕掛中」を付け、タブを #93C47D（緑）にする。「_確定」は付けない。
- ログのシートには、新しい順に1行ずつ書く。列は 日付・スレッド・変更・理由。
- 仕様の検討中の情報（判断・コメントの列、移行前に数えた件数など）は、要らなくなったら削る。
- 版を上げるときは、止まった履歴のシートを旧版に残し、新しい版から外してよい。

### 2-2. 頭の部分

| 行 | 中身 | 字 | 行の高さ | 寄せ |
|---|---|---|---|---|
| 1行目 | 題。シート名だけを書く | 14pt 太字・既定の色 | 42px | 上下中央・左・はみ出して表示 |
| 2行目から | 説明 | 10pt・#5F6368 | 21px | 上・はみ出して表示 |
| 説明の次 | 空の行1つ | ― | 21px | ― |

- 説明のセルは結合しない。長い説明は文の切れ目で行を分ける。

### 2-3. 節と表

| 行 | 字 | 行の高さ | 寄せ | 線・塗り |
|---|---|---|---|---|
| 節の見出し | 11pt 太字 | 30px | 下・はみ出して表示 | 線なし |
| 列の見出し | 10pt 太字 | 42px | 上下中央・折り返す | 下に太い線（SOLID_MEDIUM、#202124） |
| 表の中の区切りの行 | 11pt 太字 | 表の行と同じ | 表の行と同じ・はみ出して表示 | #F1F3F4 で塗る |
| 一覧の表の行 | 10pt・#202124 | 21px の倍数 | 上 | 下に細い線（SOLID、#E8EAED） |
| 判断の表の行 | 10pt・#202124 | 30px の倍数 | 上下中央 | 下に細い線（SOLID、#E8EAED） |

- 判断の表は「判断」か「所感」の列がある表。「確定」の列がある表は一覧の表として扱う。
- 罫線は表ごとにいったん全部消してから引き直す。縦の線は引かない。
- 列の見出しのフィルタの印で字が切れる列は広げる。
- 表の終わり → 空の行1つ（21px）→ 次の節の見出し。注記の行は表のすぐ下に置き、そのあとに空の行を1つ入れる。注記の字は淡い字（#5F6368）。
- 表が1つのシートは、列の見出しの行まで固定する。表が2つ以上のシートは固定しない。

### 2-4. 行が増えるシート（ログ・履歴）

- 300行目まで（すでに超えていれば少し先まで）、線と書式を先に入れておく。
- 読む列（変更・メモ）だけを折り返す。あまり読まない列（ID・場所・結果など）は右端で切る。
- 行の高さは中身に合わせてよい。多少の乱れは許す。
- GAS が行の番号で読むシートは、頭の部分の空の行を足さずに今の形のままでよい。

## 3. 作業の進め方

1. 新しく作るときは、見本のシートを写して始める（置き場所はスキル cl-style-spreadsheet）。
2. 作る前に、シートの構成（シート名・節・列・列幅）の案を示し、依頼した人の承認を得てから作る。
3. 作ったら、各シートの書式を読み直して、この文書と食い違いがないかを確かめる。
4. 作り終えたら、ログのシートに最初の1行（作成）を書く。

## 4. 塗り方

- 表が小さく、直すところが少ないときは、Sheets の道具で塗る（4-1.）。
- 行の多いシート、シートを丸ごと塗り直すとき、型との食い違いを確かめるときは、GAS に頼む（4-2.）。

### 4-1. Sheets の道具

Google Sheets の道具（update_spreadsheet）は spreadsheets.batchUpdate をそのまま渡す。決まりと request の対応は次のとおり。

| 決まり | request | 指定 |
|---|---|---|
| 枠の線を隠す・列の見出しまで固定 | updateSheetProperties | gridProperties.hideGridlines、gridProperties.frozenRowCount |
| タブの色・隠す | updateSheetProperties | tabColorStyle、hidden |
| 行の高さ・列幅 | updateDimensionProperties | pixelSize |
| 要らない行・列を消す | deleteDimension | ― |
| 字・色・寄せ・折り返し・余白 | repeatCell | userEnteredFormat の textFormat（fontFamily・fontSize・bold・foregroundColorStyle）、horizontalAlignment、verticalAlignment（TOP・MIDDLE・BOTTOM）、wrapStrategy（WRAP・CLIP・OVERFLOW_CELL）、padding |
| 区切りの行の塗り | repeatCell | userEnteredFormat.backgroundColorStyle |
| ✎ の列の見出し | repeatCell | userEnteredFormat.numberFormat（type TEXT、pattern `"✎ "@`） |
| 罫線 | updateBorders | 先に全部を NONE にし、bottom・innerHorizontal を引く |
| プルダウン | setDataValidation | condition ONE_OF_LIST、strict true、showCustomUi true（色とチップの形は Chrome で） |

- repeatCell の fields は、変える項目だけを並べる（userEnteredFormat 全体を指すと、指定しなかった書式が消える）。
- fields は括弧でまとめた書き方（userEnteredFormat(textFormat,padding)）を受け付けない。userEnteredFormat.textFormat,userEnteredFormat.padding のように1つずつ並べる（get_spreadsheet の fields も同じ）。
- 色は rgbColor に 0〜1 の小数で渡す（#202124 → 0.125, 0.129, 0.141）。
- 書式を読むときは、get_spreadsheet の ranges を小さく絞り、fields で要る項目だけを取る（広く読むと結果が大きくなる）。
- 読んだ色は丸めで1ずれることがある（#202124 → #1F2023 など）。この文書の色に読み替える。
- 日付の列は表示形式に触らない（書式なしテキストにすると、本物の日付が通し番号に見える）。道具で日付を書くときは、頭に ' を付けて文字のまま入れる。

### 4-2. GAS（paint.js）

型「標準」を塗る（塗る）と、型との食い違いを一覧で返す（点検）の2つができる。どの行が題・節・列の見出し・区切り・表かは GAS が見分けず、Claude が「設計図」（JSON）で渡す。チップの色・形・入力の拒否は GAS では付けない（1-5. のとおり Chrome で付ける）。

GAS は受け口のスプレッドシートに付けてあり、そのシート「ログ_リクエスト」に頼みごとの行を書くと、1分ごとの見回り（トリガー poll）が拾って実行する。Chrome で実行のボタンを押す必要はない。

ログ_リクエスト の使い方：

- 新しい行を、表のいちばん上（列の見出しのすぐ下）に差し込む。見回りは下の古い行から順に実行する。
- 列は7つ。

| 列 | 書くこと |
|---|---|
| 番号 | R1、R2… と進める |
| 状態 | 「待ち」と書く。GAS が 実行中 → 済（失敗すれば 誤り）に替える |
| 種類 | 塗る／点検 |
| 設計図 | 下の JSON を1行で |
| 結果 | GAS が書く（塗った request の件数、点検のずれの一覧、誤りの中身） |
| 受けた・済んだ | GAS が書く（日時） |

- 1〜2分で結果が出る。塗ったら、同じ設計図で点検の行を足し、「ずれなし」を確かめる。
- 頼む相手のファイルは、GAS を付けたアカウントで編集できるものに限る。

設計図の書き方：

```json
{ "file": "<スプレッドシートの ID>",
  "sheets": [
    { "name": "仕様_一覧", "desc": 2, "widths": [48, 160, 100, 320, 110],
      "blocks": [
        { "sec": 4 },
        { "table": { "head": 5, "last": 12, "cols": ["id", "name", "chip", "text", "chip✎"],
                     "kind": "一覧", "seps": [6, 9], "notes": [13] } } ],
      "trim": true } ] }
```

| 項目 | 中身 |
|---|---|
| file | 塗る相手のスプレッドシートの ID |
| sheets | シートごとの設計。name に書いたシートだけを塗る |
| name | シート名。頭（仕様_・ログ_・履歴_、後ろの _仕掛中）からタブの色・隠す・行を先に入れるかを決める |
| desc | 説明の行の数（2行目から） |
| widths | 列幅（px）。この数がシートの列の数になる |
| blocks | 上から順に、節の見出し（sec：行の番号）と表（table） |
| head | 列の見出しの行 |
| first | 表の最初の行。省くと head の次 |
| last | 表の最後の行。ログ_・履歴_ は省くと300行目まで |
| cols | 列の種類（下の表）を左から。依頼した人が書き込む列は末尾に ✎ を付ける |
| kind | 一覧／判断（2-3.）。省くと一覧 |
| seps | 表の中の区切りの行 |
| notes | 注記の行 |
| trim | 右・下の要らない行・列を消すか。省くと消す |

列の種類：

| 種類 | 使う列 | 寄せ・折り返し |
|---|---|---|
| id | 番号・ID（R1、T1 など） | 中央・切る・太字 |
| code | 短いコード・記号 | 中央・切る |
| chip | プルダウン（チップ） | 中央・切る |
| date | 日付・日時 | 中央・切る（表示形式に触らない） |
| name | 名前 | 左・切る |
| names | 名前がいくつも入る列 | 左・折り返す |
| text | 文（説明・メモ・条件・論点） | 左・折り返す |
| num | 数 | 右・切る |

- 種類の取り違えに気をつける。判断の表の「論点」のような文の列を name にすると、点検でずれが出る。
- 表の行の高さは、一覧は21px・判断は30px の倍数ならそのまま残す（ログ・履歴は中身に合わせた高さも残す）。
- 点検は、色を 2/255 までのずれなら同じ色とみなす。

## 5. 決めた理由

- グリッドを隠し、線を行の下だけにする：表の区切りを線ではなく行の並びで見せ、読む目を横に流すため〈仮〉。
- 色を黒とグレーと青1色にし、条件付き書式を使わない：強調が増えると何が大事か見えなくなり、条件付き書式は行を足したときに範囲が崩れやすいため〈仮〉。
- 見出しに説明を書かない：列の見出しは短いほど表が読みやすく、フィルタの印とも重ならないため〈仮〉。
- 書き込む列に塗りを付けず、見出しを青と ✎ で示す：塗りは強調に見え、行の読みを妨げるため〈仮〉。
- チップの色を Chrome で付ける：API で入力規則を貼り直すと色が消えることがあったため。
- 300行まで書式を先に入れる：行を足すたびに塗り直す手間を省くため。
