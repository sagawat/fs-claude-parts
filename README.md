# fs-claude-parts
Claude display parts (FARMSIDE)

Claude が使う共通の部品と型を置くリポジトリ（チャットの表示機能で出す部品、成果物の書式の型など）。中身は見た目と動きと決まりだけで、お客さまの情報や秘密は入れない。

# inlinetable：選べる表の見た目と共通の動き

選べる表（タスク一覧・工程一覧・メール一覧・スレッド一覧など）の、どの表でも同じ見た目と動きの決まり。表ごとの中身（集め方・段・列・ボタン・送る文・受けたあと）と、表を出す手順はスキル cl-inlinetable に従う。共通の決まりを変えるときは、部品とこの README を直す（「部品の直し方」）。

今の版：`inlinetable/it_v261125e.js`

```html
<script src="https://cdn.jsdelivr.net/gh/sagawat/fs-claude-parts@main/inlinetable/it_v261125e.js"></script>
```

## 1. 字と色

- 字は 12〜13px（列の見出しは 11px、狭い画面の項目は 14px）。太さは 400 と 500 だけにする。
- 色は CSS の変数で書く（明るい画面と暗い画面の両方で読めるようにするため）。
- 色の意味はどの表も同じにする：緑＝実行・返すなど前へ進める、青＝入れる・アーカイブ・押せない（すでにその状態）、黄＝保留、赤＝削除・出す・入れない。保留の黄は、押したときに信号の黄（#F2C200。アイコンは濃い茶 #412402）にする（text-warning は橙寄りで赤に見えるため。明るい画面・暗い画面とも同じ色）。

## 2. 列と幅・狭い画面の積み方

- 表は横幅いっぱいに取り、行は CSS の grid で組む。列の幅は表ごとの CSS で決め、項目（いちばん長い列）は残りの幅にする。長い文字は折り返し、横スクロールにしない。
- 列の並びは、チェック・番号・仕分けのボタンを左に寄せ、項目の左に置く（右端のボタンまで目を動かすと行を取り違えやすいため）。
- 見出しは1段。状態の列は置かない（段でわかるため）。
- 幅の狭い画面（560px 以下。スマホ）では見出しを消し、1行を2〜4段に積む。積み方は表ごとの CSS で決める。下の段の列には、頭に列の名前（「条件：」など）を小さく添える（`.k`）。ボタンは少し大きくする。

## 3. 札

- 優先度は青の濃淡（高＝塗りつぶし `bl3`、中＝明るい青 `bl2`、低＝ごく薄い青 `bl1`）。
- 重さと重要は赤の濃淡（大・高＝塗りつぶし `rd3`、中＝明るい赤 `rd2`、小・低＝ごく薄い赤 `rd1`）。
- 札は文字数にかかわらず同じ幅にそろえる。凡例は置かない（どの表でも同じ色なので）。

## 4. 仕分けのボタン

- 行ごとの仕分けは、アイコンだけの小さなボタン（24px 四方）。初めはどれも選ばない（表によって初めの状態を持つときは設定の `prep`）。押すと 1. の色の濃い地に白いアイコンになり、もう一度押すと外れる。指を置くと名前が出る。
- すでにその状態の行（作業中に入っている行のピンなど）は、ボタンを青で塗って押せなくする（`lk`）。
- 表示機能のボタンには既定の見た目（余白・最小幅・地の色）があり、こちらの指定が負ける。ボタンの幅・高さ・余白・色、「まとめて送る」の折り返さない指定には !important を付ける（付けないと列からはみ出す・色が付かない）。

## 5. まとめて仕分ける

- 行の左のチェックで選び、表の上のアイコン（その表の仕分けのボタンと同じもの＋消しゴム＝外す）で一度に付ける。押せないボタンに当たる行には付けない。
- 行の少ない表など、外すと決めた表には置かない（設定の `bulk:false`）。

## 6. まとめて送る

- 表の左下に、小さな「まとめて送る ↗」のボタンを置き、件数（仕分けごとの数と未選択）をその右に並べる。
- 押すと「<表の題>の仕分け（N件）：<仕分け>＝<番号 項目>、…／…／未選択＝…」がチャットに送られる。中身のない仕分けは「なし」。未選択を送るかどうかは設定の `unsel`。行を押しても何も送らない。
- どの行も仕分けていない（初めの状態から何も変えていない）ときは、押しても送らず、ボタンの所に「行の <ボタンの名前> で仕分けてください」と赤い字で出し、横に「それでも送る ↗」を置く。何も選ばずに送りたいときは「それでも送る」で送る。行のボタンかまとめての仕分けを押すと、元の「まとめて送る」に戻る。似た表が縦に並んだとき、別の表を押して空のまま送るのを防ぐため。
- まとめての仕分けの文は「チェックした行をまとめて」とし、行のボタンと取り違えないようにする。

## 6-2. 札（スレッド・回す先）

- 行の下に「↪ プロジェクト › スレッド」の札を置ける（メール一覧の回す先、タスク一覧の系統の最新のスレッドなど）。札は `IT.chip(プロジェクト, スレッド, URL)` で作り、設定の `sub(r)` に渡すと、行の下の段（`.sb`）に出る。字は 11px、枠は細い灰色、角は 6px。プロジェクトと › は薄い灰色（--text-muted）、スレッドとアイコンは灰色（--text-secondary）。メール一覧（mail-upkeep）の申し送りの札と同じ見た目。URL を渡すと押せる札（`a.chip`）になり、渡さなければ押せない札になる。札の横の小さな字は `<span class="dt">`。
- `.sb` の左の余白は、表ごとの CSS で列に合わせる（例：タスク一覧は番号の列の頭にそろえる `.sb{margin-left:52px}`）。

## 7. ページ送り

- 段の行が10件を超えたら、段ごとに10件ずつに区切り、段の最後の行の下・左側にページ送り（‹ 1 / 5 ›）を置く。

## 8. 並べ替え

- 設定で `sort` を持つ列だけ、見出しを青の文字にして押せるようにする。押すとその列で並べ替え（もう一度押すと逆順）、見出しに ↑・↓ を添える。並べ替えは段の中で行い、番号は動かさない。

## 9. 送信済み

- 送ったら表を「送信済み」にし、選んだ仕分けを残したまま押せなくする（ページ送りと並べ替えは使える）。「まとめて送る」のボタンを「✓ 送信済み」の文字に替え、題の横にも「✓ 送信済み」を添える。送信済みの表は全体を薄く（不透明度 0.5）し、まとめての仕分けを隠す（今の表と見分けるため）。
- 仕分けと送信済みは、ブラウザの記憶（localStorage）にも書く。KEY は `<スレッド名>_<表の略号>_<その表の何回目か>`（例 f_統合情報管理_82_n_tt1）にし、同じスレッドで表を出し直すときは番号を進める。記憶は消えることがあるので、確かな記録は送った文とする。

## 10. 段の見出し

- 段の見出しは、行の上に 12px・太さ 500・灰色で置く。空の段は省く（`keep:true` の段は空でも出す）。
- 見出しの横に、緑の小さな文字で「着手可」（`go:true`）か、灰色で件数（`unit` を指定。「7本」など）を添える。
- 表の上に、小さく題（`title`。「タスク一覧」など）を置く。送る文の頭にも同じ題を使う（どの表から送ったかがわかるように）。

## 11. 設定の項目（`IT` に渡すもの）

- `f`：行の配列の各要素の名前（例 `['no','t','p','w','m']`）。`no` がなければ 1 から振る。
- `secs`：段の並び `{id, name, go, keep, col, rows}`。`go:true` で「着手可」、`keep:true` で空でも出す。`rows` を持たず、下の `rows` と `grp` で段を決めてもよい。
- `rows`・`grp(r)`：段を行の状態から決める表（スレッド一覧）で使う。`grp` は段の id を返す。
- `cols`：列の並び `{a, h, v, sort}`。`a` は grid の区画の名前（`c`＝チェック、`s`＝仕分けのボタンは部品が作る）、`h` は見出し（文字か、最初の段を受けて返す関数）、`v(r, 段)` は中身の HTML、`sort(r)` は並べ替えの値（あれば見出しが押せる）。
- `btns`：仕分けのボタン `{c, l, s, i, col}`（記号・名前・件数での短い名前・アイコン・色 `g`／`a`／`y`／`r`）。
- `title`：表の題（送る文の頭にも使う）。`item(r)`：送る文の各項目。`unsel`：false で未選択を送らない。`off`：初めの状態（`prep` で付けた保留など）から外して未選択に戻した行を、この名前で送る（例 '外す'）。`unit`：段の件数の単位（あれば件数を出す）。`bulk`：false でまとめて仕分けを置かない。`ord`：初めの並べ替えの列。`lock(r, c)`：押せないボタン。`prep(r)`：行の初めの状態。`ex(r)`：行の下の囲み（`.ex`）。`sub(r)`：行の下の段（`.sb`。札を置く。6-2.）。`extra(G)`：件数の後ろに足す文。`key`：記憶の KEY（9.）。
- 札は `IT.b(値, IT.PRI)`（優先度）、`IT.b(値, IT.WT)`（重さ）、`IT.b(値, IT.UR)`（重要）で作る。

## 12. 部品の直し方

- 今の版を元に直し、新しい版の名前（`it_vYYMMDDa.js`。同じ日の2版目は b、c…）で inlinetable/ に上げる。同じ名前で上げ直さない（古い版が cdn.jsdelivr.net のキャッシュに残るため）。古い版は消さない（前のスレッドの表が読み込んでいるため）。
- 上げたら、この README の「今の版」と読み込みの1行、スキル cl-inlinetable の読み込みの1行を新しい版に直す。
- リポジトリへの上げ下ろしは Claude が行う。スレッドにリポジトリを書き込みつきでつなぎ（add_repo。佐川の承認が要る）、作業場所に写しを取って git で push する。つなげないときは Chrome の GitHub の画面で上げる。新規ファイルの画面（エディタ）には中身を入れられないので、「Upload files」の画面（`/upload/main/inlinetable`）で作業場所のファイルを渡す。
- 列の幅やボタンを変えたとき、新しい表を作ったときは、出したあとに Chrome でそのチャットを開き、仕分けのボタンが列に収まっているか、ページ送り・並べ替え・送信済みが動くかを確かめる。
- 表示機能の中では cdn.jsdelivr.net のスクリプトは読み込めるが、CSS のファイル（link）は読み込めなかった。そのため CSS はスクリプトの中に持たせ、読み込んだときに style として書き込む。
